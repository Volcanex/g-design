Shipping the edition

Rendered markdown gets the .prose class and nothing else. Width caps at 68 characters, the line height opens up to 1.65, and headings keep the interface scale so documents and dashboards feel like one product.

How publishing works

An edition is a frozen static build. The pipeline compiles every post, stamps the grid, and swaps the symlink; nothing is rendered at request time. Rolling back is pointing the symlink at the previous edition.

Publish is the same word the whole way through: the Publish button makes a Published toast and a published edition.
  • Posts are files under pages/, one directory per post
  • Drafts never leave the machine they were written on
  • Images are downscaled at compile time, not upload time
g edition publish
# builds, verifies, swaps the symlink in one step

Numbers in text

Inline figures such as 1,241,082 requests or a P95 of 118 ms stay in the text face; tabular alignment is for columns, not sentences.

Where markdown stops

.prose is the only place markdown is rendered. Every other slot in the interface is plain text: a table cell, a badge, a page heading, a tooltip, a menu item, a chart label. Chrome has no markdown renderer, so syntax handed to it survives on screen as literal asterisks and backticks.

Authored markdown reaches those slots constantly, because titles and summaries are so often lifted from the first line of a body. Flatten at the boundary with g.plain() rather than trusting the source:

td.textContent = g.plain(note.title);

It handles the truncated case too, which is the one that actually bites: a title cut to eight words keeps its opening ** and never sees the closer.
