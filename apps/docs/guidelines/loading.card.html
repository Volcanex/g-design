The rules

first paintContent enters once with the stagger: 4px rise, 200ms ease-out, 30ms per sibling. Never scroll-triggered, never replayed.
chromeThe sidebar and top bar persist across navigation. They never re-render, move or blink; only content answers.
page changeOld content sinks out in 100ms (fade, 4px). The next view sweeps in with the same stagger as first load, so navigation and arrival feel like one system.
interruptionRapid navigation cancels the pending swap; the last destination wins. No queue, ever.
slow dataA skeleton mirrors the final layout exactly, waits 350ms before appearing so quick loads never flash it, and shimmers left to right. Lists and tables get skeletons; compact elements get an inline spinner; under about a second, nothing at all.
reduced motionEverything above falls back to crossfades. Feedback stays, movement goes.
apig.swap(view, update) is the whole mechanism: mark the container .view.enter and hand it new content.
real pagesFull document navigations get the same choreography from CSS alone via @view-transition, with speculation-rules prerender for instant arrival. Try the two-page demo.

Change page: the frame's chrome holds still while the content swaps. Slow load: skeletons hold the exact layout, then the real rows replace them in place.
